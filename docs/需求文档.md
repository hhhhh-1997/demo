# 绩效月报查询模块 · 需求文档

> 版本：v1.0（初稿）
> 关联文档：[问题清单.md](./问题清单.md)
> 数据来源：`data/人员月度绩效_2026-05至07.xlsx`

---

## 1. 项目概述

某科技公司需要对各部门人员的月度绩效数据进行统一查询与展示。绩效数据按月生成，覆盖任务完成率、工作有效率、缺陷情况、代码评审等多个考核项。

- 人员分布在 **6 个一级部门**中。
- 岗位字典共 **12 类**，本期数据覆盖其中 **7 类**。
- 当前数据以离线文件形式存在，缺少可供管理者日常查阅的**在线视图**。

本模块目标是：以**前后端分离**架构实现一个绩效月报查询页面，提供检索、表格展示，并严格遵循数据展示规则。

---

## 2. 技术栈与架构

### 2.1 架构要求

前后端分离，通过 HTTP 接口通信：

- **前端**：负责界面交互与展示（检索、表格、加载/空/错误态）。
- **后端**：负责数据检索与业务规则，接口返回原始数据，**不在接口层做展示层修正**（如空值归并、等级码映射、精度截断）。

### 2.2 现有工程骨架（沿用）

| 层 | 技术栈 |
|---|---|
| 后端 | Spring Boot 3.4.1 / Java 21 / MyBatis-Plus 3.5.9 / MySQL 8 / Redis / MinIO |
| 前端 | Vue 3 + TypeScript + Vite + Naive UI |

### 2.3 职责边界（重要）

| 环节 | 负责方 |
|---|---|
| 空值（NULL）原样返回、数值 0 原样返回 | 后端 |
| 等级码（1~5）原样返回，不做文本映射 | 后端 |
| 分值项小数精度格式化（一位小数） | 展示层 |
| 等级码 → 中文等级文本映射 | 展示层 |
| 空值语义 / 等级码越界兜底展示为 `-` | 展示层 |

> 核心原则：**后端只做「检索」与「原始数据返回」，一切「展示规则」落在展示层；任何一层都不得静默修正数据语义。**

---

## 3. 术语与约定

| 术语 | 含义 |
|---|---|
| 分值项 | 数值越大越优的考核指标（如任务完成率），可格式化小数 |
| 等级项 | 存储为等级码（tinyint），数值大小与优劣方向**相反**（1 最优、4 最差） |
| 空值 NULL | 表示「无该项工作」，展示为 `-` |
| 数值 0 | 表示「有该项工作但得 0 分」，展示为 `0.0` |
| 兜底分支 | 等级码为 NULL 或越界时的展示逻辑，必须实现并由单测覆盖 |

## 4. 功能需求

页面由以下 **五个部分**组成，缺一不可：

1. 检索条件区
2. 数据表格区
3. 加载态
4. 空态
5. 错误态

### 4.1 检索条件区

共两个检索条件：

#### 检索条件一：一级部门

- 下拉选项**值**取 `top_dept_id`，**展示文本**取 `top_dept_name`。
- 过滤按 **ID** 进行。
- 「全部」以**空值**表达（不使用 `0`、`"all"` 等哨兵值）。
- 空值条件**不拼入**过滤逻辑。

| top_dept_id | 名称 | 本期数据行数 |
|---:|---|---:|
| 10 | 技术中心 | 70 |
| 20 | 第一事业部 | 151 |
| 30 | 第二事业部 | 147 |
| 40 | 第三事业部 | 108 |
| 50 | 第四事业部 | 53 |
| 60 | 第五事业部 | 113 |

#### 检索条件二：岗位

- 下拉选项**值**取岗位 `key`，**展示文本**取中文名。
- 过滤按 **key** 进行。
- 「全部」以**空值**表达，空值不拼入过滤逻辑。
- 字典共 **12 项**，**必须按字典全量展示**，不得按当月是否存在人员动态裁剪。
- 选中无数据的岗位（如 `hr`、`top`）时走**空态**，选项本身不消失。

### 4.2 数据表格区

- 展示检索结果明细，**单月数据量 213~216 行**。
- **默认不分页**：一次性展示全部结果。
- **表头固定**：纵向滚动时表头不随内容滚动。
- **左侧标识列冻结**：横向滚动时，左侧标识列保持可见。

### 4.3 加载态

- 数据请求进行中时，展示加载指示（如 loading 动画/占位）。

### 4.4 空态

- 检索结果为空时展示空态（如「暂无数据」提示）。
- 触发场景包括：选中无数据的岗位（`hr`、`top` 等）、过滤组合无匹配记录。

### 4.5 错误态

- 请求失败（网络异常、服务端错误等）时展示错误提示，并可重试。
- **不得吞掉异常**：错误信息需可被用户感知。

## 7. 数据处理规则（验收重点）

### 7.1 空值语义

- 分值项为 `NULL` → 表示「无该项工作」，展示为 **`-`**。
- 数值 `0` → 表示「有该项工作但得 0 分」，展示为 **`0.0`**（遵循一位小数规则）。
- 二者语义**相反**，不可互相替代，**任何环节都不得将 0 归并为「无数据」**。

各列 NULL / 0 值分布（对照列：缺陷情况、软需设计同时存在 NULL 与 0）：

| 列 | NULL 数 | 0 值数 |
|---|---:|---:|
| 代码评审 | 639 | 0 |
| 学习及能力提升 | 621 | 0 |
| 概要设计 | 574 | 0 |
| 软需设计 | 513 | 1 |
| 缺陷情况 | 332 | 156 |
| 工作规范性 | 0 | 48 |
| 工作有效率 | 0 | 2 |
| 任务完成率 | 0 | 0 |

### 7.2 等级码映射

`pre_sales_support`、`test_quality` 存储等级码，映射关系：

| 等级码 | 等级文本 |
|---:|---|
| 1 | 超出预期 |
| 2 | 完全达标 |
| 3 | 需要提升 |
| 4 | 未达预期 |
| 5 | 无该项工作 |

- 映射在**展示层**完成，**接口返回原始等级码**。
- 等级码为 `NULL` 或**越界**时展示 **`-`**，不报错、不回落为任一等级。
- 兜底分支必须实现并由单元测试覆盖，**不得因「数据里没有」而省略**。
  - 本期数据仅出现 2、3、5，未出现 1、4、NULL 与越界值。

### 7.3 等级项不是分数

- 数值大小与优劣方向**相反**（1 最优、4 最差）。
- 任何场景下**不得**对这两列（`pre_sales_support`、`test_quality`）求和、求平均或按数值排序。
- 界面上须与分值项做**视觉区分**。

### 7.4 数值精度

- 分值项统一**保留一位小数**（含 `work_normativity` 这类整型存储的列，展示为 `80.0`）。
- 等级项为整型等级码，**不参与**小数格式化。
- `work_effect_rate` 超过 100 时按**原值**展示，**不得截断至 100**。

### 7.5 月份处理

- `month` 为定宽字符串，**直接做字符串比较**，不得转换为日期类型再比较。

### 7.6 默认不分页

- 单月数据量 213~216 行，一次性展示全部结果。
- 保证表头固定、左侧标识列横向滚动时冻结。

## 9. 代码规范要求

- **可读性**：命名清晰、结构合理。
- **必要注释**：关键业务规则（空值语义、等级码映射、精度处理）需有注释说明。
- **完整错误处理**：**不得吞掉异常**；异常需向上传递并在展示层转化为错误态。
- **职责分离**：展示规则集中在展示层，检索逻辑集中在后端，不跨层修正。

## 10. 验收标准

1. 五个部分（检索区、表格区、加载态、空态、错误态）全部实现。
2. 两个检索条件按字典全量展示，空值表达「全部」，无数据岗位选中走空态。
3. 空值语义正确：NULL → `-`，0 → `0.0`，二者不混淆。
4. 等级码映射正确，NULL / 越界兜底展示 `-`，且兜底分支有单测覆盖。
5. 等级项不做求和/平均/数值排序，视觉上与分值项区分。
6. 分值项统一一位小数，`work_effect_rate` 超 100 不截断。
7. 月份按字符串比较，不转日期类型。
8. 默认不分页，表头固定、左侧标识列冻结。
9. 接口返回原始数据，展示规则不在后端静默修正。
10. 错误态可感知，无异常被吞。
