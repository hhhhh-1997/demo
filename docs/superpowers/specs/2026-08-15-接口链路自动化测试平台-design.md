# 接口链路自动化测试平台 — 设计规格说明书

> **版本**: V1.0
> **日期**: 2026-08-15
> **状态**: 待评审
> **依据**: CLAUDE.md（技术选型 / 后端红线 / 前端规范）、现有 demo 系统鉴权接口（`POST /api/auth/login`、`POST /api/auth/logout`、Sa-Token `token-name: Authorization`）

---

## 1. 背景与目标

在现有「综合计划储备项目管理」系统内新增一个「自动化测试」菜单模块，提供**接口链路自动化测试**能力：测试员以可视化方式编排一条由 HTTP 请求组成的链路（**登录 → 业务接口 → 登出**），一键执行，系统按顺序调用各接口；**任一步响应不符合预期即中止**，记录该步的请求/响应快照与断言失败原因，供回溯。

### 目标

1. 可视化编排接口链路（步骤 = HTTP 请求 + 断言 + 变量提取）。
2. 顺序执行整条链路，支持变量在步骤间传递（如登录返回的 token 注入后续请求头）。
3. 失败即中止（停在失败接口），记录完整异常。
4. 运行历史与每步结果可回溯。

### 非目标（YAGNI）

- 不做浏览器 UI 自动化（页面跳转 / 按钮点击 / E2E）——用户已确认仅接口链路。
- 不做录制回放、不做代码脚本编辑。
- 不做并发压测、定时任务、消息通知、报告导出。
- 不做 WebSocket 实时推流（接口执行快，结果落库后前端轮询即可）。
- 不做多租户、不做跨系统调用（仅测本系统 `/api/**`）。

## 3. 关键决策记录（ADR）

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| A1 | 测试范围 | 仅接口链路，不做浏览器 UI 自动化 | 用户明确要求（需求变更，砍掉 UI 自动化） |
| A2 | 步骤模型 | 单一「HTTP 请求」步骤，含 method/path/headers/query/body/asserts/extracts | 接口链路本质是顺序 HTTP 调用，无需多步骤类型 |
| A3 | 变量传递 | `{{name}}` 占位符 + JSONPath 提取 | 登录返回 token 需注入后续请求头；简单可读 |
| A4 | 断言粒度 | HTTP 状态码 + JSONPath 字段比对（EQUALS/CONTAINS/EXISTS） | 覆盖「符合预期」判定 |
| A5 | HTTP 客户端 | Spring `RestClient` + 关闭非 2xx 抛错 | 需捕获 4xx/5xx 原始响应做断言 |
| A6 | 失败语义 | 任一步失败即中止，后续步骤标 SKIP | 对应「停在该接口」需求 |
| A7 | 实时性 | 结果落库 + 前端轮询，不做 WebSocket | 接口执行快，无需推流 |
| A8 | 并发 | MVP 单工作线程串行执行（显式 ThreadPoolExecutor） | 避免资源竞争，后期再放开 |

## 4. 数据模型（MySQL）

| 字段 | 类型 | 说明 |

| status | tinyint | 0=PASS / 1=FAIL / 2=SKIP |
| request_snapshot | json | 请求快照（脱敏，见 §11） |
| response_snapshot | json | 响应快照（status/headers/body） |
| assert_detail | text | 断言明细（期望 vs 实际） |
| error_msg | varchar(1000) | 错误信息 |
| start_time / end_time | datetime | 起止时间 |

## 5. 步骤模型（`at_step.params` JSON）

一个步骤就是一个 HTTP 请求，完整 JSON 结构：

```json
{
  "method": "POST",
  "path": "/api/auth/login",
  "headers": { "Content-Type": "application/json" },
  "query": { "current": "1" },
  "body": { "username": "{{username}}", "password": "{{password}}" },
  "asserts": [
    { "type": "STATUS", "expected": "200" },
    { "type": "JSON", "jsonPath": "$.code", "op": "EQUALS", "expected": "200" },
    { "type": "JSON", "jsonPath": "$.data.token", "op": "EXISTS" }
  ],
  "extracts": [ { "name": "token", "jsonPath": "$.data.token" } ]
}
```

- **method**：`GET` / `POST` / `PUT` / `DELETE`。
- **path**：相对路径，实际 URL = `场景.base_url + path`。
- **headers / query / body**：均支持 `{{变量}}` 占位符；`body` 为 JSON 对象（序列化后发送）。
- **asserts**：
  - `STATUS`：HTTP 状态码断言，`expected` 为字符串。
  - `JSON`：响应体 JSONPath 断言，`op` ∈ `EQUALS` / `CONTAINS` / `EXISTS`；`EXISTS` 无需 `expected`。
- **extracts**：从响应体用 jsonPath 提取值存入变量，供后续步骤引用。

---

## 6. 变量传递机制

每次运行维护一个**变量上下文** `Map<String,Object>`（每 run 隔离，不跨 run 共享）：

1. **初始化**：先载入 `at_scenario.variables` 预置变量（如 `username`、`password`）。
2. **替换**：执行某步骤前，将 headers（值）、query（值）、body（字符串化后）中的 `{{name}}` 用上下文值替换；未找到变量则替换失败 → 该步标 FAIL。
3. **提取**：步骤执行成功后，按 `extracts` 用 JSONPath 从响应体取值写回上下文（如登录后 `token`）。
4. **典型链路**：
   - 登录步骤 → 提取 `$.data.token` → `token` 入变量；
   - 业务步骤 headers 带 `Authorization: {{token}}`；
   - 登出步骤同样带 token 调 `POST /api/auth/logout`。

> 变量名用小写字母 / 数字 / 下划线；占位符正则 `\{\{([a-zA-Z_][a-zA-Z0-9_]*)\}\}`。

## 7. 执行引擎与「失败中止」

`ApiChainEngine.run(scenarioId)`：

1. 加载场景 + 步骤（按 `step_order` 升序）→ 建 `at_run`(status=RUNNING) → 投递显式 `ThreadPoolExecutor`（红线：禁用 `Executors`；MVP core=1, max=1，有界队列）。
2. 顺序遍历步骤：
   - 变量替换 → 构建请求 → `RestClient.exchange()` 发送；
   - 记 `request_snapshot` / `response_snapshot`；
   - 逐条执行 `asserts`，任一不符 → 抛断言失败；
   - 成功后执行 `extracts` 提取变量；
   - 写 `at_step_result`(status=PASS)。
3. **失败分支**（HTTP 异常 / 断言不符 / 变量缺失）：
   - 当前步写 `FAIL` + `assert_detail`（期望 vs 实际）+ `error_msg`；
   - 置 `at_run.status=FAILED` + `fail_step_id`；
   - **后续所有步骤标 `SKIP`，不再执行**（即「停在该接口」）；
   - 结束本次运行。
4. 全部通过 → `at_run.status=SUCCESS`。

## 8. 断言实现

- 依赖 `com.jayway.jsonpath:json-path`。
- `RestClient` 配置 `defaultStatusHandler` 不抛非 2xx，`exchange()` 返回 `ResponseEntity<String>`，从而对 4xx/5xx 也能拿到原始 body 做断言。
- `STATUS` 断言：比对 `responseEntity.getStatusCode().value()` 与 `expected`（字符串比较）。
- `JSON` 断言：用 `JsonPath.read(body, jsonPath)` 取实际值，按 `op` 比较：
  - `EQUALS`：`String.valueOf(actual).equals(expected)`；
  - `CONTAINS`：`String.valueOf(actual).contains(expected)`；
  - `EXISTS`：`JsonPath` 能读到且非 null。
- 断言失败信息记录「断言路径 / 操作 / 期望值 / 实际值」到 `assert_detail`。

## 9. API 接口设计（REST，前缀 `/api/autotest`）

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| POST | `/api/autotest/scenario` | 新建场景（含 steps 数组） | `autotest:scenario:add` |
| GET | `/api/autotest/scenario/page` | 场景分页列表 | `autotest:scenario:list` |
| GET | `/api/autotest/scenario/{id}` | 场景详情（含 steps） | `autotest:scenario:list` |
| PUT | `/api/autotest/scenario/{id}` | 更新场景（整体替换 steps） | `autotest:scenario:edit` |
| DELETE | `/api/autotest/scenario/{id}` | 删除场景 | `autotest:scenario:delete` |
| POST | `/api/autotest/scenario/{id}/run` | 触发执行，返回 runId | `autotest:scenario:run` |
| GET | `/api/autotest/run/{id}` | 运行详情 + 每步结果 | `autotest:scenario:list` |
| GET | `/api/autotest/run/page` | 运行历史分页 | `autotest:scenario:list` |

- Controller 入参用 `@Validated` / `@Valid` 校验（红线 #4）。
- 场景保存接口：传入 `steps` 数组，后端删除旧步骤后整体重建（`@Transactional`，红线 #6）。

## 10. 前端设计（`src/views/autotest/`）

### 10.1 场景管理页 `scenario/index.vue`

- 场景表格（分页、增删改查）。
- 步骤编排器（内嵌或抽屉）：
  - 步骤列表，可上移 / 下移 / 增删；
  - 每步卡片：方法下拉（GET/POST/PUT/DELETE）→ 路径输入 → headers 键值对 → query 键值对 → body JSON 编辑器 → 断言列表（类型/路径/操作/期望值）→ 提取列表（变量名/JSONPath）；
  - 场景级「预置变量」编辑区（密码类字段 `type=password` 脱敏）。
- 统一 `el-form` + `rules` 校验；禁止散落裸 axios（统一走 `api/autotest.ts` 封装）。

### 10.2 运行结果页 `run/detail.vue`

- 步骤结果列表（PASS/FAIL/SKIP 状态标签）。
- 失败步骤展开：请求快照 / 响应快照 / 断言明细 / 错误信息。
- 运行中轮询 `GET /api/autotest/run/{id}`（1s 间隔）刷新状态。

### 10.3 接入

- 新增 `api/autotest.ts`、路由 `/autotest/*`。

## 11. 异常记录

每步结果 `at_step_result` 落库：

- **请求快照** `request_snapshot`：method / path / headers / query / body —— **密码字段与 `Authorization` 头一律脱敏**（打码）。
- **响应快照** `response_snapshot`：status / headers / body。
- **断言明细** `assert_detail`：断言路径 / 操作 / 期望值 / 实际值。
- **错误信息** `error_msg`：异常类型 + 摘要。

`at_run` 额外记录 `fail_step_id` + `error_msg` 作为整链失败摘要。

## 13. 红线合规

| 红线 | 落实 |
|------|------|
| #2 敏感信息脱敏 | 密码、`Authorization` token 在 `request_snapshot`、日志、接口返回中一律打码；预置密码前端 `type=password` |
| #4 参数校验 | 场景 / 步骤 / 运行 DTO 用 `@Validated` |
| #6 事务一致 | 场景 + 步骤整体保存加 `@Transactional`；执行过程中每步结果即时落库，不做长事务 |
| #9 线程安全 | 显式 `ThreadPoolExecutor` 传参，禁用 `Executors` |
| SQL 注入 | MyBatis-Plus `#{}` 占位符，无拼接 |

## 14. 测试计划

- **后端单元测试**：变量替换（占位符 / 缺失变量）、断言比较（EQUALS/CONTAINS/EXISTS）、JSONPath 提取。
- **后端集成测试**：`ApiChainEngineIT`（H2 内存库 + 真实启动的本地 HTTP 服务或 MockMvc 模拟目标接口）验证「登录 → 业务 → 登出」链路成功与失败中止、SKIP 标记。
- **前端**：`npm run typecheck` + `npm run build`；手工验证场景编排、运行、失败结果展示。
