## 1. 背景与目标

对综合计划类储备项目进行全生命周期管理，覆盖「储备项目维护 / 储备项目论证 / 储备项目审核 / 统一储备库」四大环节。

本设计在需求文档（V2.0）与原型图基础上，**新增**两项目标：

1. **用户认证与权限控制**：完整 RBAC（用户 / 角色 / 菜单权限，含管理界面，菜单级 + 按钮级动态配置）。
2. **自动化用例测试**：后端集成测试 + 单元测试。

### 非目标（YAGNI）

- 不做多租户、工作流引擎、消息通知、附件上传（MinIO 配置已存在但本期不接入业务）。
- 不做前端组件级 / E2E 自动化测试（用户已确认范围仅「后端集成+单元」）。
- 不做原型图顶栏「全局搜索框 + 通知铃铛」的真实功能（无需求支撑，UI 占位处理）。

## 5. 状态机

### 5.1 状态枚举（`ProjectStatus`）

`DRAFT(草稿)` / `PENDING_REVIEW(待论证)` / `REVIEW_REJECTED(论证退回)` / `PENDING_AUDIT(待审核)` / `AUDIT_REJECTED(审核退回)` / `PENDING_ISSUE(待下达)` / `ISSUED(已下达)`

### 5.2 转移白名单

| 当前状态 | 操作 | 目标状态 | 触发模块 |
|---------|------|---------|---------|
| 草稿 / 论证退回 / 审核退回 | 提报 | 待论证 | 维护 |
| 待论证 | 论证通过 | 待审核 | 论证 |
| 待论证 | 论证不通过 | 论证退回 | 论证 |
| 待审核 | 审核通过 | 待下达 | 审核 |
| 待审核 | 审核不通过 | 审核退回 | 审核 |
| 待下达 | 下达 | 已下达 | 统一储备库 |

**实现**：Service 层显式转移白名单校验（非法转移抛业务异常），写操作 `@Transactional`。论证/审核结论写入 `project_review` / `project_audit`，项目状态作为唯一事实源。

### 5.3 派生视图

- 论证模块「论证通过」= `status = 待审核` 的项目
- 审核模块「审核通过」= `status = 待下达` 的项目
- 统一储备库 = `status ∈ {待下达, 已下达}` 的项目

### 5.4 统计口径

- 论证通过率 = 论证通过数 ÷ (论证通过数 + 论证退回数) × 100%（不含待论证）
- 审核通过率 = 审核通过数 ÷ (审核通过数 + 审核退回数) × 100%（不含待审核）
- 储备库总投资（亿元）= Σ investment_amount（元）÷ 100000000，`BigDecimal` 计算，保留 1 位小数

## 6. 权限模型（RBAC）

### 6.1 预置角色

| role_key | 名称 | 权限范围 |
|----------|------|---------|
| admin | 系统管理员 | 全部模块 + 系统管理 |
| maintainer | 维护员 | 储备项目维护 |
| reviewer | 论证员 | 储备项目论证 |
| auditor | 审核员 | 储备项目审核 |
| reserve | 储备库管理员 | 统一储备库 |

### 6.2 权限字符串（`模块:操作`）

- `project:add` / `project:edit` / `project:delete` / `project:submit` / `project:export`
- `review:execute` / `review:view`
- `audit:execute` / `audit:batch` / `audit:view`
- `reserve:issue` / `reserve:view` / `reserve:export`
- `system:user` / `system:role` / `system:menu` / `system:dept` / `system:dict`

### 6.3 认证与鉴权

- 登录 `POST /auth/login` 调用 `StpUtil.login(loginId)` 返回 Sa-Token token + 用户信息 + 角色集 + 权限集。
- 后端：`@SaCheckPermission("project:submit")` / `@SaCheckRole("maintainer")` 注解鉴权；接口层 + 数据归属校验（写操作校验当前用户是否有权）。
- 权限注入：自定义 `StpInterface` 实现 `getPermissionList` / `getRoleList`，从 `sys_user_role` / `sys_role_menu` 实时加载。
- 前端：路由守卫按权限动态生成菜单；`v-permission` 指令控制按钮显示/置灰；请求拦截器附加 `token`，401 跳登录。

### 8.3 设计系统与视觉还原（混合方案）

- **交互骨架用 Element Plus**：表格 `el-table`（含 `selectable` 控制行复选框）、表单 `el-form` + `rules`、下拉 `el-select`、弹窗 `el-dialog`、日期 `el-date-picker`。
- **视觉复刻用自定义 scoped CSS + CSS 变量**：移植原型的 `--primary/success/warning/danger/info`、`--bg-primary/secondary/tertiary/card/hover`、`--border/text-*`、`--shadow` 等 token，复刻渐变按钮、`badge-*` 徽标、渐变 `stat-card`、毛玻璃弹窗（`backdrop-filter: blur` + 缩放过渡）。
- **主题**：默认**暗色**；`stores/theme` 切换时同时写入 `html.dark`（联动 Element Plus 暗色）与自定义 CSS 变量，localStorage 持久化。
- **图标**：Element Plus 图标映射（`fa-paper-plane→Promotion`、`fa-eye→View`、`fa-edit→Edit`、`fa-trash→Delete`、`fa-check-circle→CircleCheck`、`fa-warehouse→OfficeBuilding` 等），不额外引入 Font Awesome。
- **自绘展示组件**：`StatCard`（渐变图标卡片）、`StatusTag`（badge-* 徽标）、`SmartPagination`（精确对齐 §7.1 分页规范）。

### 8.4 关键交互规范（对齐 §7 通用功能）

- 分页默认 5 条/页；≤7 页全显，>7 页智能省略号；筛选/操作后回第 1 页。
- 金额显示：表格 `(amount / 10000)` 万元（千位分隔，右对齐）；储备库总投资 `(amount / 100000000)` 亿元。
- 导出 CSV：UTF-8 BOM，文件名 `<模块名>_<日期>.csv`。
- 主题：默认暗色，顶栏一键切换，localStorage 持久化，刷新不丢失（SPA 单文档，无需 iframe 联动）。
- 空数据：空状态占位 + 「暂无匹配的数据」。
- 弹窗/确认框：复用 Element Plus `el-dialog` / `ElMessageBox`；删除=红、提报/下达=绿。

## 9. 测试策略

### 9.1 单元测试（JUnit 5 + Mockito）

- 状态机转移：合法转移通过、非法转移抛异常（如 草稿→下达、已下达→提报）。
- 项目编码生成：跨月重置、同月递增、位数补零。
- 金额换算：元↔万元↔亿元精度（`BigDecimal`，禁 `float/double`）。
- 权限判断逻辑。

### 9.2 集成测试（`@SpringBootTest` + MockMvc + H2 MySQL 兼容）

覆盖全部 REST 接口，关键用例：

- **全链路**：登录 → 新增 → 提报 → 论证通过 → 审核通过 → 下达，断言各阶段状态与记录落库。
- **非法状态转移**：草稿直接下达 / 已下达再提报 → 返回业务错误。
- **越权**：无权限角色调用接口 → 403。
- **参数校验**：空名称、非法金额（≤0 / 非数字）、缺失必填 → 400。
- **金额换算**：数据库存元、接口/展示层换算正确。
- **敏感信息**：接口返回不含密码；日志不打印密码/token。

**执行**：`mvn test` 一键跑通，不依赖外部 MySQL/Redis（用 H2 + mock 掉 Redis 相关 Bean）。

## 10. 风险与边界

- H2 与 MySQL 的方言差异：测试用 H2 MySQL 兼容模式，`date`/`decimal` 语法需在 `schema.sql` 中显式建表；生产用 `docker-compose.yml` 的 MySQL。
- 现有 `database/*.csv` 与需求文档不一致（状态、分类、编码），需重做种子数据脚本。
- 完整 RBAC 管理界面是新增子系统，工作量集中在用户/角色/菜单三个管理页 + 动态菜单渲染。
