# 绩效月报查询模块 · 设计规格（Spec）

> 版本：v1.0 ｜ 日期：2026-08-14 ｜ 状态：待评审
> 关联：需求 `docs/需求文档.md` · 问题清单 `docs/问题清单.md` · 原型 `docs/prototype/performance-report-query.html`

---

## 1. 概述

### 1.1 背景

某科技公司需要对各部门人员月度绩效数据提供统一在线查询。数据目前为离线 xlsx（`data/人员月度绩效_2026-05至07.xlsx`，642 行，2026-05/06/07 三个月），缺少可供管理者日常查阅的在线视图。

### 1.2 目标

前后端分离实现绩效月报查询页面：检索 + 表格展示，严格遵循数据展示规则（空值语义、等级码映射、精度）。

### 1.3 非目标（本期不做）

- 加权总分、部门汇总、同比/环比、排名（问题清单 Q4 已确认不做）。
- 数据写入/编辑、权限控制、登录。
- 分页（默认不分页）。
- 原型的「模拟接口异常」开关（演示脚手架，正式实现移除）。

## 3. 架构与职责边界

前后端分离，通过 HTTP 通信。**核心原则：后端只做「检索」与「原始数据返回」，一切「展示规则」落在前端展示层；任何一层不得静默修正数据语义。**

| 环节 | 负责方 |
|---|---|
| NULL 原样返回、数值 0 原样返回 | 后端 |
| 等级码（1~5）原样返回，不做文本映射 | 后端 |
| 检索过滤、排序 | 后端 |
| 分值项小数精度格式化（一位小数） | 前端 |
| 等级码 → 中文等级文本映射 | 前端 |
| NULL / 等级码越界兜底展示 `-` | 前端 |

## 4. 功能设计

页面由五部分组成：检索条件区、数据表格区、加载态、空态、错误态。

### 4.1 检索条件区（三个检索条件）

| 条件 | 选项值 | 展示文本 | 说明 |
|---|---|---|---|
| 一级部门 | `top_dept_id` | `top_dept_name` | 6 项（技术中心、第一~五事业部） |
| 岗位 | `role` key | 中文名 | 12 项全量，不动态裁剪 |
| 月份 | `month` | `YYYY-MM` | 2026-05/06/07，**默认 2026-07（最新月）** |

- 「全部」以空值表达（不用 `0`/`"all"` 哨兵值），空值不拼入过滤逻辑。
- 选中无数据的岗位（如 `hr`、`top`）走空态，选项本身不消失。
- 「查询」触发检索；「重置」将一级部门、岗位清空为「全部」，月份回到默认值 2026-07。

### 4.2 数据表格区

- **15 列**（展示顺序与原型一致）：

| # | 列 | 字段 | 类型 |
|---|---|---|---|
| 1 | 姓名（冻结） | `realname` | 文本 |
| 2 | 月份 | `month` | 文本 |
| 3 | 一级部门 | `top_dept_name` | 文本 |
| 4 | 二级部门 | `dept_name` | 文本 |
| 5 | 岗位 | `role_name` | 文本 |
| 6 | 任务完成率 | `task_finish_rate` | 分值 |
| 7 | 工作有效率 | `work_effect_rate` | 分值 |
| 8 | 工作规范性 | `work_normativity` | 分值 |
| 9 | 学习及能力提升 | `learning_improvement` | 分值 |
| 10 | 软需设计 | `software_design` | 分值 |
| 11 | 售前支撑 | `pre_sales_support` | 等级 |
| 12 | 缺陷情况 | `bug_condition` | 分值 |
| 13 | 概要设计 | `system_design` | 分值 |
| 14 | 代码评审 | `code_review` | 分值 |
| 15 | 测试产出质量 | `test_quality` | 等级 |

- 隐藏字段：`id`、`user_id`、`dept`、`role`、`top_dept_id`（接口仍返回，仅不展示）。
- **默认不分页**：一次性展示全部结果。
- **表头固定**：纵向滚动时表头不随内容滚动（`el-table` 的 `height`）。
- **左侧「姓名」列冻结**：横向滚动时保持可见（列 `fixed="left"`）。

### 4.3 状态视图

- **加载态**：请求进行中展示加载指示（`v-loading`）。
- **空态**：结果为空展示「暂无数据」（`el-empty`）。
- **错误态**：请求失败展示错误提示 + 重试按钮（`el-result`）。**不得吞掉异常**，错误信息需可被用户感知。

---

## 5. 检索与排序规则

- 三个检索条件按 ID / key / 字符串过滤，空值不拼入。
- **排序：`ORDER BY month DESC, id ASC`**（在后端完成，属检索范畴）。
- `month` 为定宽字符串 `YYYY-MM`，**直接字符串比较**，不转日期类型。

---

## 6. 展示规则

### 6.1 空值语义（核心）

- 分值项 `NULL` = 「无该项工作」，展示为 `-`。
- 数值 `0` = 「有该项工作但得 0 分」，展示为 `0.0`。
- **二者语义相反，不可互相替代**，任何环节不得将 `0` 归并为「无数据」。

### 6.2 等级码映射

`pre_sales_support`、`test_quality` 为等级项，存等级码，映射在展示层完成：

| 码 | 文本 |
|---:|---|
| 1 | 超出预期 |
| 2 | 完全达标 |
| 3 | 需要提升 |
| 4 | 未达预期 |
| 5 | 无该项工作 |

- 等级码为 `NULL` 或**越界**时展示 `-`，不报错、不回落为任一等级。
- 兜底分支必须实现并有单元测试覆盖（本期数据仅出现 2/3/5，仍不可省略）。

### 6.3 等级项不是分数

- 数值大小与优劣方向**相反**（1 最优、4 最差）。
- 不得对 `pre_sales_support`、`test_quality` 求和、求平均或按数值排序。
- 界面上用 `el-tag` 徽标与分值项视觉区分。

### 6.4 数值精度

- 分值项统一保留一位小数（含整型存储的 `work_normativity`，展示为 `80.0`）。
- 等级项为整型等级码，不参与小数格式化。
- `work_effect_rate` 超 100 按原值展示（上限 120），不截断。

## 7. 接口契约

- **路径 / 方法**：`GET /api/performance/monthly`
- **请求参数**（query，均可缺省或空串表示「全部」）：

| 参数 | 类型 | 说明 |
|---|---|---|
| `topDeptId` | int | 一级部门 ID，空 = 全部 |
| `role` | string | 岗位 key，空 = 全部 |
| `month` | string | 月份 `YYYY-MM`，空 = 全部（前端默认传 2026-07） |

- **统一响应体**：

```json
{ "code": 200, "msg": "success", "data": [ ... ] }
```

| 场景 | code | data | 前端表现 |
|---|---|---|---|
| 成功有数据 | 200 | 对象数组 | 表格 |
| 成功无数据 | 200 | `[]` | 空态 |
| 失败 | ≠200（如 500） | `null` | 错误态 + 重试 |

- **data 元素**：返回数据表全部 20 字段原样（NULL → JSON `null`，0 → `0`，等级码 → 1~5 整数，decimal → 数值不截断）；前端只渲染 15 列，格式化/映射在前端完成。

## 10. 测试策略

- **后端单测**：过滤（三条件拼接、空值不拼接）+ 排序（month DESC + id ASC）+ 月份字符串比较。
- **前端单测**（Vitest）：`utils/format.ts` 纯函数 ——
  - `fmtScore`：`null` → `-`、`0` → `0.0`、`120` → `120.0`。
  - `gradeBadge`：1~5 映射、`null`/越界 → `-` 兜底。
- 空值语义与等级码越界兜底分支必须有测试覆盖（验收重点）。

---

## 11. 验收标准

1. 五部分（检索区、表格区、加载态、空态、错误态）全部实现。
2. 三个检索条件按字典全量展示，空值表达「全部」，无数据岗位选中走空态。
3. 空值语义正确：NULL → `-`，0 → `0.0`，二者不混淆。
4. 等级码映射正确，NULL / 越界兜底展示 `-`，兜底分支有单测覆盖。
5. 等级项不做求和/平均/数值排序，视觉上以徽标与分值项区分。
6. 分值项统一一位小数，`work_effect_rate` 超 100 不截断。
7. 月份按字符串比较，默认排序 `month DESC, id ASC`。
8. 默认不分页，表头固定、左侧姓名列冻结。
9. 接口返回原始数据，展示规则不在后端静默修正。
10. 错误态可感知，无异常被吞。
