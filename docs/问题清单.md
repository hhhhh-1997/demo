## 一、待确认问题

### 🔴 Q1 月份检索维度缺失

需求只定义了「检索条件一（一级部门）」「检索条件二（岗位）」两个检索条件，但数据按月组织（2026-05 / 06 / 07 三个月），且标题为「月度绩效」。

**需要确认：**

- 月份是否作为第三个检索条件（下拉/单选）？
- 若否，月份如何进入查询（路由参数？固定展示最新月？）。
- 默认月份取哪个值（最新月 2026-07？）。

**影响：** 检索条件区设计、后端过滤参数、前端状态管理。

**结论：** 月份作为第三个检索条件。前端用日期组件 `el-date-picker type="month"`（`value-format="YYYY-MM"`），默认当前月、重置清空（空值 = 全部）；后端接收 `month` 参数，空串不拼入过滤。

---

### 🔴 Q2 默认排序规则未定义

需求多次强调「排序规则必须与设计文档一致」，但提供的材料中**未给出具体排序规则**。

已明确的约束：

- 等级项（`pre_sales_support`、`test_quality`）**不得按数值排序**。
- 分值项、等级项之外的列的默认排序未说明。

**需要确认：** 默认排序键是什么（`id`？`user_id`？`month`？`realname`？），升序还是降序？

**影响：** 表格默认呈现顺序，验收口径。

**结论：** 后端默认排序固定为 `ORDER BY month DESC, id ASC`；前端分值列（8 列）支持点击表头正序/倒序排序，等级项与文本列不参与排序。

---

### 🔴 Q3 接口契约未定义

前后端分离，但以下均未在需求中给出：

- 接口路径、HTTP 方法（GET/POST）。
- 请求参数命名与类型（`topDeptId`？`role`？`month`？）；「全部」的空值如何传递（缺省？`null`？）。
- 响应结构：是否统一响应体（如 `{ code, msg, data }`）；数据是裸数组还是分页包裹。
- 空态与错误态如何区分（200 + 空数组 vs 业务错误码 vs 非 200 状态码）。

**影响：** 前后端联调契约，必须先行冻结。

**结论：** `GET /api/performance/monthly`，入参 `topDeptId` / `role` / `month` 均可缺省（空 = 全部）；统一响应体 `{ code, msg, data }`，`data` 为 camelCase 记录数组；空态 = 200 + `[]`，错误态 = 500 + `{ code:500, msg, data:null }`。

### 🟡 Q4 是否存在加权 / 汇总 / 统计需求

原始 xlsx 的「字段说明」sheet 中明确提到：

- `code_review`：「仅少量行有值，**参与加权前需确认口径**」。
- 附注：「**可正常做分组、同比和排名练习**」。

这些措辞暗示可能存在「加权总分」「部门汇总」「排名」等能力，但核心需求只描述了「查询展示」。

**需要确认：**

- 本期范围是否包含：加权总分列、部门汇总、同比/环比、排名？
- 若包含，各分值项权重如何定义？

**影响：** 直接决定后端是否需要聚合计算逻辑；等级项「不得求和/平均」与汇总需求的边界。

**结论：** 本期不做加权/汇总/排名，仅查询展示。

### 🟡 Q5 `role_name` 映射与字典数据的归属

- `role_name` 由 `role`（key）映射生成，非原始字段。
- 岗位字典（12 类）与一级部门字典（6 个）需**全量展示**。

**需要确认：**

- 字典数据由**前端硬编码**还是**后端接口返回**？
- `role_name` 的映射放在前端还是后端？若后端返回，是否仍要求接口「返回原始等级码」一样，`role` key 与 `role_name` 同时返回？

**影响：** 字典维护位置、是否引入字典接口。

**结论：** 字典（一级部门/岗位）与 `role_name` 由前端硬编码维护；后端同时返回 `role` key 与 `role_name`。

## 三、潜在不一致点

### 🟢 D1 `test_quality` 等级值描述偏差

需求文本称「本期数据只出现了 2、3、5 三种取值」，但核实结果中 `test_quality` 仅出现 **2、5**（无 3）；`pre_sales_support` 才同时出现 2、3、5。

**结论：** 不影响实现（兜底分支已要求覆盖 1/4/NULL/越界），仅需在文档中修正为「两列合并出现 2/3/5」，避免误导。

### 🟢 D2 `work_normativity` 类型标注不一致

需求数据结构表标注为 `int`（取值 0/10/…/100），而 xlsx 的「字段说明」sheet 标注为 `decimal(4,1)`。

**结论：** 以需求文档 `int` 为准（实际数据为整数），展示层按「分值项统一一位小数」格式化为 `80.0` 即可。建议统一口径，避免后端建表时类型选择歧义。

### 🟢 D3 引用的「设计文档」未提供

需求多处提到「与设计文档一致」（尤其排序规则），但仓库 `docs/` 目录为空，未见独立设计文档。

**结论：** 若存在独立的「设计文档」，需一并提供，以便排序规则等细节对齐；否则以本需求文档为准。

## 四、决策结论汇总

| 项 | 结论 |
|---|---|
| 月份检索 | 作为第三个检索条件（日期组件），默认当前月，重置清空（空 = 全部） |
| 默认排序 | 后端 `month DESC, id ASC`；前端分值列支持正序/倒序排序 |
| 字典与 role_name | 前端硬编码字典与 `role_name`，后端返回 `role` key + `role_name` |
| 数据装载 | 提供建表 SQL + 导入脚本，三个月全量入库 |
| 接口 | `GET /api/performance/monthly?topDeptId=&role=&month=`，统一响应体 `{ code, msg, data }` |
| 汇总/统计 | 本期**不做**加权/汇总/排名，仅查询展示 |
